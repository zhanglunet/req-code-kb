# kb-survey-req

## 背景

#11 实战演练的真需求：用户要找 GitHub 上目前最流行的知识库相关
开源仓库，分析这些仓库可以借鉴的地方，然后整理成知识库。
短名单已经出过（`kb-survey-shortlist.md`）：10 个仓库，四类，
star 数、语言、许可证、最近 push 均已实时核实。
深挖分析也已完成（`kb-survey-analysis.md`）：每仓读 README +
至少一份架构/文档关键页，给出组织、检索、索引、回流、协作五点，
以及按价值排序的“最值得借的 10 条”。

## 需求

- 需求原文（用户原话）：“在 github 找到目前最流行的知识库相关
  的开源仓库，分析这些仓库，找到可以借鉴的地方，然后整理成知识库”。
- 短名单口径：10 个仓库，按 star 数排，四类各取最靠前；只收
  一年内有 push 的（最近 push 在 2026-05-22 至 2026-11-26 之间）。
- 写 5 张知识页：总览页（最值得借的 10 条总表 + 三条共识 + 方法说明），
  代码知识库页（aider、deepwiki-open），RAG/文档知识库页
  （dify、ragflow、anything-llm），笔记/个人知识库页（AFFiNE、
  思源笔记、logseq），文档/Wiki 知识库页（docusaurus、wiki.js）。
- 每页都要有：仓库名 + star 数 + 语言 + 许可证 + 最近 push +
  借鉴点（注明对应 issue #12/#13/#14/#15/#16 或新想法）+
  来源（仓库 + 文件/章节）。
- 每页页首写明方法，照实说：本页由 2026-11-26 调研整理
  （README/架构文档），非 reqkb build 从代码抽取（build 只解析
  Python，这 10 仓大多不是 Python）；借鉴点只借思路，AGPL/自定义
  协议仓库不复用代码。数字只用分析文件里已核实的，不自己编、
  不从记忆里补。

## 验收标准

- [ ] 5 张知识页齐全，结构与现有页一致（需求原文 / 来源 / 内容 / 对应关系 / 诚实标注）
- [ ] 每页有方法说明、仓库一览表、至少 3 条借鉴点、来源清单
- [ ] 数字与分析文件、短名单文件一致（star 数、语言、许可证、最近 push）
- [ ] 本地网站生成通过，5 页 HTML 逐页核验通过
- [ ] 不碰现有 kb/ 与 cli-anything-kb/kb/，不推 GitHub、不开 PR、不合并
