## 内容

### meta/docusaurus

- **组织单位**：页（Markdown/MDX 文件）+ 侧边栏树。最小单位是一篇文档 = `docs/` 下一个 `.md`/`.mdx` 文件，frontmatter 控制标题、URL、排序位置。文件夹即章节，`sidebars.js/json` 声明页如何嵌套成导航树，也可由文件夹结构自动生成（autogenerated）。内容分三种插件：docs（文档）、blog（博客）、pages（自定义页）——三种内容形态共用同一套站生成管线。
- **检索**：全文搜索，但搜索是“爬已生成的站”，不是查源码。官方路线是 Algolia DocSearch：爬虫每周爬一次已构建好的网站，把全部内容聚合进 Algolia 索引，前端直接调 Algolia API 查询。预设自动生成 `sitemap.xml` 供爬虫用；不合免费条件或站不公开时可自跑爬虫。社区路线：Typesense DocSearch、`docusaurus-search-local`（Lunr，构建时生成客户端索引，零外部服务）、或自己写 `SearchBar` 组件。没有向量检索、没有图检索；检索对象是渲染后的页面。
- **索引与切分**：构建期/爬虫期做，不在写作期做。DocSearch 爬虫按官方 v3 模板配置切分（`initialIndexSettings` 只在建索引时生效，改配置官方建议删索引重爬）；本地搜索插件在构建时把全站内容打成一个客户端索引。切分单位是页/标题段，不是整库；作者只管写文件，切分是管线的事。
- **回流/防过时**：没有内容新鲜度检测，靠版本化 + 横幅 + 重爬。防过时 = 版本快照（见⑤）+ 每页顶部横幅（`unreleased`/`unmaintained`/`badge`），告诉读者“你在看的不是最新版”。回流 = 改文件 → 提交 → 重新构建部署；DocSearch 每周重爬自动跟上新内容。没有任何“对照真实改动校验预测”的闭环，这是它与 req-code-kb 的 harvest 最大的不同。
- **协作与版本化**：一切皆 git 文件；版本化 = 整目录快照。没有可视化编辑器，“每次编辑都是改一个文件走 Git”（PR review 即协作流程）。`npm run docusaurus docs:version 1.1.0` 做三件事：整份 `docs/` 复制到 `versioned_docs/version-1.1.0/`、当前侧边栏复制到 `versioned_sidebars/`、版本号追加进 `versions.json`（新到旧排序）。关键区分：current 版本由文件系统位置定义（`docs/` 文件夹，默认标 `Next`、走 `/docs/next/*`）；latest 版本由导航行为定义（默认走 `/docs` 的那个版本）。两者可相同可不同。官方明确建议：版本数保持 <10；不要给 patch 版切版本（semver 下无行为变化）；老版本归档办法是“最后构建一次，静态产物另存为不可变独立部署，永久 URL 外链”，而不是永远参与构建——因为每多一个版本构建成本就多一份。另：i18n 内置（Crowdin，`i18n/<locale>/docusaurus-plugin-content-docs/current/`），插件化扩展（sitemap、RSS、PWA 各为一个插件）。

### requarks/wiki（Wiki.js）

- **组织单位**：路径即树的一页（page），不建文件夹。每页活在一个路径下，如 `/infra/backups`，树由路径推断出来，不用先建文件夹（与 BookStack 的书/章/页层级相反，更像维基百科的有机链接网）。每页创建时自选编辑器：Markdown（CodeMirror + 实时预览）、可视化编辑器、AsciiDoc、原始 HTML；2.5.201 起可在编辑器间转换，转换前自动快照进历史。页带标签（tag）、多语言（locale）、可自定义导航菜单；另有实时链接关系图谱（graph view）。
- **检索**：数据库全文搜索为主，可插拔换引擎。默认零配置：PostgreSQL 全文搜索（2.x/3.x 用 `pg_trgm` 扩展的专用搜索模块），支持布尔搜索 + 标签过滤。可替换引擎：Elasticsearch、Algolia、Azure Search、Solr、Manticore——搜索是模块，可换。无原生向量检索；链接图谱是导航辅助，不是检索主力。
- **索引与切分**：整页为单位，索引由数据库维护。内容全在数据库里（页、修订、用户、权限、配置、上传资产都是 Postgres 行），搜索索引是数据库全文索引，无独立的切分/分块层。索引重建是已知的高峰成本来源之一（与渲染 burst、Git 同步定时任务并列）。
- **回流/防过时**：有“内容进 git”的双向回流，但无新鲜度判断。Git 存储模块（双向同步）：页保存即提交并推送 Markdown 到 GitHub/GitLab/Bitbucket/任意 Git 远端；反向在仓库里改 Markdown、push 后，wiki 按设定间隔（定时任务，如每 5 分钟）或实时拉回入库。文件路径结构可配（如 `/docs/{page-path}/index.md`）。3.0 更进一步：文档版本可映射到 Git 分支/tag（如 `v2.1` 跟 `release/v2.1` 分支、`latest` 跟 `main`）。冲突是软肋：force push、rebase、两边同时改同一页会把同步模块卡住，需管理员手动 resync；官方/实测建议指到“没人会改写历史”的仓库。关键限制：Git 里的只是第二份人类可读拷贝，不含用户、权限与资产——真正的备份是 `pg_dump` + `config.yml`；Git 不能替代数据库备份。没有“这页是否过时”的自动判定；防过时靠页历史 + 可视化 diff + 一键恢复。
- **协作与版本化**：数据库是真相，Git 是镜像；权限细到路径。协作：评论、实时多人协同编辑、Excalidraw 白板、GraphQL API（`/graphql`，官方 UI 与外部脚本用同一套 API，API key 是绑定到组的 JWT）。版本化双层：① 数据库内每页完整修订历史，可视化对比、写修改理由（相当于 commit message）、一键恢复；② 可选的 Git 同步把每次保存变成一次 git commit。权限体系（最值得借鉴的一点）：按组 + 按页路径规则，规则可匹配精确路径、前缀、后缀或正则，可再按 locale 与站点（多站点同部署）限定；管理员继承全部权限；单个授权可显式或从父路径继承。例：外包只能读 `/handbook/**`、写 `/onboarding/**`。认证可插拔：本地、LDAP/AD、SAML 2.0、OIDC/OAuth2、Azure AD、Okta、Keycloak、Google/GitHub/Discord/Slack 等社交登录，可选 MFA；其余几乎所有设置都在管理 UI 里改，只有数据库连接与端口在 `config.yml`。

## 诚实标注

- Docusaurus 证明了“文件即内容、构建即发布、版本即快照目录”这条路能撑到 66k★；它的短板（搜索依赖外部爬虫、无回流校验、无编辑器）恰好是 req-code-kb 已有 harvest 和 ask 的长处。
- Wiki.js 3.0 的 Git 分支映射、实时同步细节来自二手深挖文，未在一手代码中逐行核对；Docusaurus 的 DocSearch 记录切分粒度来自其官方爬虫模板的通用设计，`search.mdx` 原文只写到“爬虫聚合全部内容进索引 + sitemap 驱动”，未逐字段展开。落到实现时建议以官方模板/代码为准再确认一次。
- 版本现状提醒（核实过的坑）：2.x 稳定版是 2.5.316（2026-10-02），发布已移到 `requarks/wiki-v2` 维护仓；主仓现在是 3.0 beta（默认分支 `scarlett`，要求 PostgreSQL 16/17/18 + `ltree`/`pg_trgm`、Node.js 26），2.x → 3.0 无原地升级，需导出 `.wkbackup` 再导入新实例，且模块设置、Git 同步、SSO 都要重配。Git 模块要求指向整个仓库，不支持子目录/子模块。
- wiki.js 是 AGPL-3.0，只借思路、不复用代码。
